# 榜单字段说明

页面有 v1 / v2 / v3 三套并行列集，v3 是默认视图（130 列：72 个 v3 列 + 17 个 v2 列 + 描述列）。本仓库统一使用 v3 字段。

## 核心指标

| 字段 | 名称 | 含义 | 范围与参照 |
|---|---|---|---|
| `combined_v3` | 综合 | 多模式加权后的总分，页面标签 "Combined RP" | 0–100，榜首约 69.8（≤40B）/ 65.8（闭源） |
| `combined_se_v3` | ± | 综合分的标准误。**小于 1 才值得信**，超过 5 的分数基本不可用 | — |
| `cw_score_v3` | CW | 创意写作。原文口径：graded on craft, instruction following, originality, errors and slop | — |
| `rp_score_v3` | RP | 角色扮演 | — |
| `erp_score_v3` | ERP | 露骨内容能力分。**衡量"会不会写"的唯一有效指标** | 中位 41.3，p90 61.5，最高 71.6 |
| `drp_score_v3` | DRP | 暗黑内容能力分 | 最高约 75.3 |
| `literal_combo_v3` | 错误 | 事实/指令类错误，越低越好 | 榜首约 4.8，中位约 9 |
| `slop_combo_v3` | slop | AI 腔指数，越低越干净 | p10 25.1，中位 40.5，p90 53.9 |

## 两个"投递比"字段（最容易误读）

| 字段 | 名称 | 含义 |
|---|---|---|
| `nsfw_v3` | 露骨投递比 | >1.0 比要求更露骨，1.0 按要求，<1.0 会净化 |
| `darkness_v3` | 暗黑投递比 | 同上口径，针对暗黑内容 |

方法论原文：

> NSFW / Darkness — content delivery ratios, not quality signals. NSFW measures erotic content delivery: above 1.0 = pushes more explicit than prompted, 1.0 = delivers as asked, below 1.0 = sanitizes.

这两个字段是**语气倾向描述**，不计入综合分，也不是质量分。全站 `nsfw_v3` 范围约 0.57–1.78，中位 0.92。

投递比高不代表会写：`nsfw_v3` 榜首是 Zwielicht 27B（1.78），但它的 RP 是 0.0、综合 1.7。前排大量模型都是"不管你要不要都硬塞"。

## slop 的实际构成

2026-09-02 的规则集更新说明：

> The slop detector's rule set was rebuilt from a corpus scan of 23,000 scored prose cells. 215 new patterns were added — predominantly class 2 (purple prose) n-gram and phrase patterns mined from high-frequency AI-generated text. 163 rules that never fired across the corpus were retired. The overall set moved from 798 to 850 rules.

所以 slop 是**规则库匹配**，不是 LLM 评委打分。850 条模式，分 5 个严重度等级加权，主要针对紫色散文（过度修饰、比喻堆砌）和模板套话（"空气中弥漫着…"、"一丝不易察觉的…" 这类）。

它出现在两个地方：CW 打分的一个维度，以及 `RP Slop floor`（100 = 无扣分）这个乘法惩罚因子。

## 参数量字段

`parameter_count_b` 对开源模型可信，对 Proprietary 常为 0。`scripts/lib.py` 里的 `under40()` 会排除 Proprietary 和 `evaluation_tier != 1.0` 的条目。

MoE 没有独立字段，只能按 `display_name` 和 `lineage` 里的 `A?B` 模式识别（如 `26B-A4B`）。

## rank 字段的真实含义

`rank` 是**按 `cw_score_v3` 降序**的名次，不是综合分名次。验证方式：取 `rank` 前 6 名，它们的 CW 严格递减，而综合分顺序完全不同。

2026-11-21 快照的 top 6：

| rank | 模型 | CW | 综合 |

| 1 | Qwen4 Max (Thinking) | 88.9 | 51.6 |
| 2 | Claude Fable 5.2 | 87.6 | 65.8 |
| 3 | GPT-6 Astra | 87.4 | 32.9 |
| 4 | GPT-6.1 Sol | 86.5 | 43.8 |
| 5 | Kimi K3.1 Pro | 86.0 | 61.8 |
| 6 | Claude Opus 5.5 | 86.0 | 54.7 |

## 官方基座 vs 社区微调

榜单同名列里混着官方模型和社区微调，两者的评分可以差几十分。例子：

| 模型 | 条目 | ERP | 综合 |
|---|---|---|---|
| MiMo V2.6 Flash | 官方 (Xiaomi) | 15.0 | 52.8 |
| MiMo V2.6 Flash | MOPD Yamz Uncensored | 52.7 | 65.0 |
| Gemma-4 26B-A4B | Base (google) | 37.8 | 53.7 |
| Gemma-4 26B-A4B | SOMPOA-Heresy | 46.6 | 59.6 |
| DeepSeek V4.1 Flash | 1017 (DeepSeek) | 42.5 | 63.1 |
| DeepSeek V4.1 Flash | 1017 Uncensored | 48.0 | 65.4 |

匹配网关或官方 API 的模型时，必须对准官方基座那一行，不能按名字模糊取最高分。`scripts/gateway.py` 的 `RULES` 表就是为这件事维护的。

## 分档说明

方法论里的 4 档，影响权重：`evaluation_tier` 只有等于 1.0 的条目进入正式排名；本仓库的筛选函数默认丢弃其他档位。
